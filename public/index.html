Chapter 5: Memory Management (Operating System Concepts)
Direct academic study reference based on the textbook Operating System Concepts (Silberschatz, Galvin, Gagne) for university Operating Systems courses.
1. Contiguous Memory Allocation (Slide 7)
In contiguous memory allocation, each process is contained in a single contiguous section of physical memory:
  • Multiple-partition allocation: Memory is divided into several partitions. Each partition contains exactly one process.
  • Hole: A block of available free memory. Holes of various sizes are scattered throughout memory.
  • When a process arrives, it is allocated memory from a hole large enough to accommodate it.
  • When a process terminates, it frees its partition, and adjacent free holes are merged together (coalescing).
2. Dynamic Storage-Allocation Strategies (Slide 8)
How to satisfy a request of size n from a list of free holes:
First-Fit:

Allocate the first hole that is big enough. Searching can stop as soon as a hole that fits is found. Generally the fastest algorithm.

Best-Fit:

Allocate the smallest hole that is big enough. Must search the entire list unless ordered by size. Produces the smallest leftover hole.

Worst-Fit:

Allocate the largest hole available. Must search the entire list. Produces the largest leftover hole, which may be more useful than tiny leftover fragments.

3. Slide 9 Exercises & Solved Solutions
Exercise 1: Core Benchmark
Partitions: [100, 500, 200, 300, 600] KB | Processes: [212, 417, 112, 426] KB
• Fixed Partitions mode (the leftover is internal fragmentation):
  – First Fit: P1 to 500, P2 to 600, P3 to 200. P4 (426 KB) fails because only the 100 KB and 300 KB partitions are left. Internal fragmentation = 559 KB.
  – Best Fit: P1 to 300, P2 to 500, P3 to 200, P4 to 600. All 4 processes succeed (4/4). Internal fragmentation = 433 KB.
  – Worst Fit: P1 to 600, P2 to 500, P3 to 300. P4 fails. Internal fragmentation = 659 KB.
• Dynamic mode (the preset loads in this mode): every hole is split, so internal fragmentation is 0 KB and the waste appears as external fragmentation instead: 659 KB (First Fit), 359 KB (Best Fit) and 659 KB (Worst Fit).
Exercise 2: Exact Fits & Unusable Holes
Partitions: [50, 100, 200, 350] KB | Processes: [45, 50, 80, 120, 200] KB
• Dynamic mode (First Fit and Best Fit place all 5): P1 (45 KB) takes the 50 KB partition and leaves a 5 KB hole. P2 (50 KB) goes to the 100 KB partition, P3 (80 KB) to the 200 KB partition and leaves a 120 KB hole, P4 (120 KB) fills that 120 KB hole exactly, and P5 (200 KB) goes to the 350 KB partition.
• Exact fit: only P4, which fills its hole with nothing left over. The Results tab shows Exact Fits: 1.
• Unusable hole: the 5 KB hole next to P1 is smaller than every request (the smallest is 45 KB), so it can never be used. The Results tab shows Unusable Small Holes: 1.
• Fixed Partitions mode: there are no exact fits. First Fit and Best Fit place 4 of 5 (P5 fails) and Worst Fit places 3 of 5.
Exercise 3: Process Arrival Order Effect
Partitions: [300, 100, 350, 600, 200] KB | Processes: [115, 500, 210, 90, 430] KB
• First Fit and Best Fit: place 4 of 5 processes in both orders. Only the 600 KB partition can hold P2 (500 KB) or P5 (430 KB), so at most one of them can ever be placed.
• Worst Fit: in the original order P1 (115 KB) takes the largest hole (600 KB) first, so P2 (500 KB) fails and only 3 of 5 are placed. Sorted from largest to smallest, the 500 KB process claims the 600 KB partition first and Worst Fit also reaches 4 of 5.
• Lesson: arrival order can change the result, but sorting is not a guaranteed fix. Use the sort button on the Setup tab, then compare the three algorithms on the Comparison tab.
4. Memory Fragmentation (Slide 10)
  • External Fragmentation: Total memory space exists to satisfy a request, but it is not contiguous; storage is fragmented into a large number of small holes scattered across memory.
  • Internal Fragmentation: Memory allocated to a process is slightly larger than requested memory. The unused space within the allocated partition is internal to that partition and cannot be used by other processes.
  • 50-Percent Rule: Analysis shows that given N allocated blocks, another 0.5N blocks will be lost to external fragmentation. That is, 1/3 of memory may be unusable!
